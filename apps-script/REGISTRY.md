# Реестр объектов в Google Таблице

У каждого объекта один постоянный ID: `HIG-0001`, `HIG-0002`… Этот же ID видят CRM
(экран «Объекты»), Google Таблица и сайт (`hig_id` в `site/data/listings.json`).

Как это работает:
1. GitHub Actions (`update-public-catalog.yml`) каждый час забирает посты каналов и запускает
   `scripts/build_object_registry.py`. Репосты одного объекта (тот же адрес, комнаты и площадь)
   склеиваются в один объект, даже если цена поменялась.
2. ID хранятся в `site/data/registry-ids.json` и никогда не меняются и не переиспользуются.
3. Реестр публикуется в `site/data/registry.json` (только то, что и так есть в публичных постах).
4. `registry.gs` раз в час переносит его в закрытую Google Таблицу, где агенты дописывают
   собственника, телефон, заметки и ставят статус «Сдан/Продан/Занят/Снят».

## Что сделать один раз

1. Создать новую Google Таблицу «Реестр объектов HiG» (доступ только команде, не «всем по ссылке»:
   там будут телефоны собственников).
2. Расширения → Apps Script → вставить `registry.gs` → Сохранить.
3. Выбрать функцию `setupRegistry` → Выполнить → разрешить доступ.

Скрипт создаст лист «Объекты», заполнит его и включит обновление раз в час.
В таблице появится меню «Реестр» → «Обновить из каналов».

## Связь со сделками

В калькуляторе сделки (CRM, `/test/`) есть поле «Объект из реестра». Оно заполняется само, когда агент
вставляет ссылку на пост, или вручную (`HIG-0001`). После отправки сделки CRM вызывает веб-приложение
реестра (`?action=closeObject`): объект получает статус «Сдан» (аренда) или «Продан» (продажа),
«Дату сделки» и строку в «Заметках», и в CRM уходит в «Архив». Если объект снова опубликуют в канале
после даты сделки, синхронизация вернёт ему статус «Свободен».

Чтобы включить: в редакторе скрипта Развернуть → Новое развертывание → Веб-приложение,
«Выполнять от имени: меня», «Доступ: все». URL вписать в `REGISTRY_API_URL` в `test/index.html`.
Веб-приложение отдаёт наружу только ID и статусы, телефоны собственников не уходят.
